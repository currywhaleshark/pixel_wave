# 픽셀아트 제작 규격 — 픽셀 파도

이 문서는 **아트 제작자용 사양서**입니다. 코드 쪽 단일 진실 원천은 [`js/assets.js`](../js/assets.js)이며, 여기 표와 항상 일치해야 합니다.

## 1. 해상도 규격

| 항목 | 값 |
|---|---|
| 월드 해상도 | **480 × 270** |
| 화면 출력 | 정확히 **2배** 확대 (960 × 540), 보간 없음(nearest) |
| 게임 로직 좌표 | 960 × 540 (`CFG.pxUnit = 2` → 월드 픽셀 1 = 로직 2) |
| HUD·한글 텍스트 | **960 × 540 레이어에 별도 렌더** (확대되지 않아 또렷함) |

- 모든 스프라이트 좌표·크기는 **월드 픽셀(480×270 기준)** 로 표기합니다.
- 스프라이트는 그릴 때 자동으로 월드 픽셀 격자에 스냅됩니다(반픽셀 뭉개짐 방지).
- 320×180은 채택하지 않았습니다 — 적탄 반경이 월드 1.7px까지 줄어 탄막 가독성과 작은 피격판정 표현이 무너집니다. 480×270에서 적탄은 월드 약 2.5~3.5px로, 확대 후 5~7px이 되어 읽힙니다.

## 2. 시트 구성

| 시트 | 경로 | 내용 |
|---|---|---|
| main | `assets/sprites.png` | 플레이어·돌고래·잡몹·거북·탄·진주 |
| boss | `assets/bosses.png` | 보스 7종 |

- 투명 배경 PNG(RGBA).
- **프레임은 가로로 이어 붙입니다**: 프레임 i의 좌상단 = `(x + i*w, y)`.
- 파일이 없어도 게임은 정상 동작합니다(도형 폴백).

## 4. 색·톤 가이드

앨범아트 기준 — 픽셀 + 파스텔 바닷속 + 칩튠.

| 용도 | 색 |
|---|---|
| 인어 머리 | `#ff9ec7` |
| 인어 꼬리 | `#3fd8c7` |
| 진주 | `#ffffff` → `#e8d8ff` → `#b39ddb` |
| 큰 진주 | `#ffffff` → `#ffe9a8` → `#f2b64e` |
| 적탄(기포) | `#cfeaff` 테두리 + 반투명 속 |
| 적탄(가시) | `#ffffff` → `#ffb3cf` |
| 등불/기뢰 | `#ffd66e` |
| 별탄 | `#eafffb` / `#8ef0e2` |
| 유령 | `#d8f4ec` (반투명 25%↔90%) |

**탄막 가독성이 최우선입니다.** 적탄은 배경과 명도 차가 크게, 외곽 1px 밝은 테두리 권장. 배경은 채도를 낮춰 탄이 묻히지 않게.

## 5. 작업 흐름 (점진 교체)

1. `assets/sprites.png`에 해당 칸을 그린다.
2. `js/assets.js`에서 그 항목의 `on: false` → **`on: true`**.
3. 새로고침 — 그 캐릭터만 스프라이트로 바뀌고 나머지는 도형 유지.

> `on` 플래그가 없으면 "시트는 로드됐지만 아직 안 그린 칸"이 **투명하게 그려져 적이 사라집니다.** 반드시 그린 항목만 켜세요.

폴백 구조:

```js
if (Sprites.draw(ctx, 'enemy.fish', x, y, { t })) return;  // 스프라이트
drawTemporaryShape();                                       // 도형
```

## 6. 검증 체크리스트

- `?debug` → **6번 키**로 픽셀 렌더 ON/OFF 비교
- 480×270에서 적탄이 배경에 묻히지 않는가
- 캐릭터가 월드 픽셀 격자에 붙어 떨림 없이 움직이는가
- 어두운 스테이지(4·5)에서 실루엣이 읽히는가
- 모바일 최저 FPS (디버그 오버레이 `min` 값)
