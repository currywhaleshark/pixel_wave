# 픽셀아트 제작 규격 — 픽셀 파도

이 문서는 **아트 제작자용 사양서**입니다. 코드 쪽 단일 진실 원천은 [`js/assets.js`](../js/assets.js)이며, 여기 표와 항상 일치해야 합니다.

## 1. 해상도 규격

| 항목 | 값 |
|---|---|
| 월드 해상도 | **480 × 270** |
| 화면 출력 | 정확히 **2배** 확대 (960 × 540), 보간 없음(nearest) |
| 게임 로직 좌표 | 960 × 540 (`CFG.pxUnit = 2` → 월드 픽셀 1 = 로직 2) |
| HUD·한글 텍스트 | **960 × 540 레이어에 별도 렌더** (확대되지 않아 또렷함) |

- 모든 스프라이트 좌표·크기는 **월드 픽셀(480×270 기준)** 로 표기합니다.
- 스프라이트는 그릴 때 자동으로 월드 픽셀 격자에 스냅됩니다(반픽셀 뭉개짐 방지).
- 320×180은 채택하지 않았습니다 — 적탄 반경이 월드 1.7px까지 줄어 탄막 가독성과 작은 피격판정 표현이 무너집니다. 480×270에서 적탄은 월드 약 2.5~3.5px로, 확대 후 5~7px이 되어 읽힙니다.

## 2. 시트 구성

| 시트 | 경로 | 내용 |
|---|---|---|
| main | `assets/sprites.png` | 플레이어·돌고래·잡몹·거북·탄·진주 |
| boss | `assets/bosses.png` | 보스 7종 |

- 투명 배경 PNG(RGBA).
- **프레임은 가로로 이어 붙입니다**: 프레임 i의 좌상단 = `(x + i*w, y)`.
- 파일이 없어도 게임은 정상 동작합니다(도형 폴백).

## 4. 색·톤 가이드

앨범아트 기준 — 픽셀 + 파스텔 바닷속 + 칩튠.

| 용도 | 색 |
|---|---|
| 인어 머리 | `#ff9ec7` |
| 인어 꼬리 | `#3fd8c7` |
| 진주 | `#ffffff` → `#e8d8ff` → `#b39ddb` |
| 큰 진주 | `#ffffff` → `#ffe9a8` → `#f2b64e` |
| 적탄(기포) | `#cfeaff` 테두리 + 반투명 속 |
| 적탄(가시) | `#ffffff` → `#ffb3cf` |
| 등불/기뢰 | `#ffd66e` |
| 별탄 | `#eafffb` / `#8ef0e2` |
| 유령 | `#d8f4ec` (반투명 25%↔90%) |

**탄막 가독성이 최우선입니다.** 적탄은 배경과 명도 차가 크게, 외곽 1px 밝은 테두리 권장. 배경은 채도를 낮춰 탄이 묻히지 않게.

## 5. 작업 흐름 (점진 교체)

1. `assets/sprites.png`에 해당 칸을 그린다.
2. `js/assets.js`에서 그 항목의 `on: false` → **`on: true`**.
3. 새로고침 — 그 캐릭터만 스프라이트로 바뀌고 나머지는 도형 유지.

> `on` 플래그가 없으면 "시트는 로드됐지만 아직 안 그린 칸"이 **투명하게 그려져 적이 사라집니다.** 반드시 그린 항목만 켜세요.

폴백 구조:

```js
if (Sprites.draw(ctx, 'enemy.fish', x, y, { t })) return;  // 스프라이트
drawTemporaryShape();                                       // 도형
```

## 6. 검증 체크리스트

- `?debug` → **6번 키**로 픽셀 렌더 ON/OFF 비교
- 480×270에서 적탄이 배경에 묻히지 않는가
- 캐릭터가 월드 픽셀 격자에 붙어 떨림 없이 움직이는가
- 어두운 스테이지(4·5)에서 실루엣이 읽히는가
- 모바일 최저 FPS (디버그 오버레이 `min` 값)

## 7. 픽셀 폰트

현재 텍스트는 전부 `Fonts.f()`를 거칩니다([`js/fonts.js`](../js/fonts.js)). 폰트 파일이 없으면 **sans-serif로 자동 폴백**하므로, 파일을 넣는 순간 전 화면이 한 번에 바뀝니다.

### 배치

```
assets/fonts/Galmuri9.woff2   (+ .ttf)
assets/fonts/Galmuri11.woff2  (+ .ttf)
```

`index.html`의 `@font-face` 이름과 `js/fonts.js`의 `faces[].family`가 일치해야 합니다.

### 왜 크기가 다른 폰트를 둘 이상 두는가

비트맵 계열 픽셀 폰트는 **고유 크기의 정수 배**로만 또렷합니다(11px 폰트를 13px로 그리면 뭉개짐).
하나만 쓰면 11·13·16px이 전부 11px로 뭉쳐 **위계가 사라집니다.** 9px + 11px 두 개를 두면:

| 요청 | 실제 | | 요청 | 실제 |
|---|---|---|---|---|
| 11 | 11 (11×1) | | 22 | 22 (11×2) |
| 13 | 11 | | 30 | 33 (11×3) |
| 16 | 18 (9×2) | | 36 | 36 (9×4) |
| 20 | 22 | | 44 | 44 (11×4) |

`Fonts.f()`가 로드된 페이스 중 요청에 가장 가까운 조합을 자동으로 고릅니다. **합성 볼드는 쓰지 않습니다**(픽셀 폰트에 가짜 볼드를 씌우면 획이 뭉개짐) — 강조는 색과 크기로.

### 폰트 후보 (한글 지원)

| 폰트 | 고유 크기 | 라이선스 | 비고 |
|---|---|---|---|
| **갈무리 (Galmuri)** | 7 / 9 / 11 / 14 | OFL | 픽셀 게임용으로 설계, 한글·일문·라틴 폭넓음. 현재 코드의 기본 가정 |
| **둥근모꼴 / Neo둥근모** | 16 | OFL | 한국 도트 게임의 고전. 16px 고유라 HUD엔 다소 큼 |
| **Dung Geun Mo** | 16 | 개인·상업 무료 | 위와 동계열 |

> 다른 폰트를 쓰려면 `js/fonts.js`의 `faces` 배열(패밀리명·고유 크기)과 `index.html`의 `@font-face`만 바꾸면 됩니다.

### 적용 폰트 (2026-08-27)

**갈무리(Galmuri) 2.40.3, OFL-1.1** — `assets/fonts/`에 Galmuri9 / Galmuri11 / Galmuri11-Bold(woff2, 합계 ~1.1MB) + `OFL.txt`.
Galmuri11에는 **진짜 볼드**가 있어 합성 볼드 없이 강조가 됩니다(`Fonts.f(px, true)`).

### 텍스트를 어느 레이어에 그릴 것인가 — 실측 결론

캔버스 `fillText`는 **픽셀 폰트에도 안티에일리어싱을 적용**합니다(측정: 11px에서 AA 픽셀 비율이 sans-serif와 동일한 수준). 이걸 피하려고 두 가지를 시험했습니다.

| 시도 | 결과 |
|---|---|
| 비트맵 내장 TTF (`Galmuri11Bitmap`) | **렌더 불가** — 아웃라인이 없어 캔버스에서 아무것도 안 그려짐(0픽셀). 폐기 |
| 월드 레이어(480)에 11px → 2배 확대 | **더 뭉개짐** — 11px의 AA가 2×2 블록으로 증폭 |
| **960 레이어에 22px (고유의 2배)** | **가장 또렷** — 채택 |

즉 **텍스트는 960 레이어에 고유 크기의 2배 이상으로** 그리는 현재 방식이 맞습니다. 픽셀 폰트를 native 크기(11px)로 그리는 것은 오히려 손해입니다. `Fonts.f()`가 요청 크기를 배수로 스냅하므로 호출부는 신경 쓸 필요가 없습니다.

### 화면 맞춤 (정수 배율)

픽셀아트는 비정수 배율로 늘리면 픽셀이 뭉개집니다. `fitCanvas()`가 뷰포트에 맞는 **480×270의 정수 배**로만 표시 크기를 정합니다(1280×800 → 960×540 = 정확히 2배). 화면이 480×270보다 작을 때만 소수 배율로 축소합니다.
